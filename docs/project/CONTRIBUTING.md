# 参与开发

当前文档基线：`v2.0.0`。每次发布前请同步维护 README、CHANGELOG 与受影响的 `docs/` 页面。

感谢你改进 2048。请从 `main` 的最新版本创建分支，并确保改动保持经典 2048 的公平规则、AI 信息边界、回放兼容性和六语言界面。

## 本地开发

需要 Node.js 22.13 或更高版本：

```bash
npm ci
npm run dev
```

提交前运行完整验证：

```bash
npm run verify
```

AI 行为或性能改动还应运行：

```bash
npm run benchmark:ai:suite
```

## 改动要求

- 一次提交聚焦一个清晰目标，避免无关重构。
- 新行为必须配套可重复的测试；修复缺陷时应增加回归覆盖。
- 不得让 AI 预知随机块、自动撤回，或改变有效移动后的 90%/10% 生成分布。
- 修改日志编码时必须继续重建并验证旧格式，或明确提供迁移路径。
- 界面文字需同步维护联合国六种官方语言，并检查键盘、触摸和 RTL 布局。
- 新增 UI 原语放入 `app/ui/`；页面控制器、领域模块和样式文件须遵守 [`docs/architecture.md`](./docs/architecture.md) 的边界与长度门槛。
- 不提交 `node_modules`、`dist`、缓存、测试报告、密钥或本地环境文件。

## 发布约定

GitHub 和在线 Sites 始终来自同一个 `main` 提交。发布时先完成验证、提交并推送，再使用该完整提交 SHA 创建 Sites 版本并完成线上冒烟测试；不要维护第二份源码。
